Building real-time dashboards for financial data presents a unique challenge: how do you manage rapidly changing state (like stock prices or order books) without overwhelming the frontend or drifting out of sync with the backend?

Traditional approaches often involve:
1.  **Polling**: Too slow for real-time data.
2.  **Redux + WebSockets**: Requires manual "glue code" to merge socket events into the global store.
3.  **Server Components**: Great for initial load, but tricky for high-frequency live updates.

In our latest dashboard iteration, we're experimenting with a new architecture: **Synchronizing TanStack DB directly with NATS JetStream**.

## The Architecture

The concept is simple but powerful: treat the browser's local state as a database replica that syncs with the backend via NATS streams.

-   **Backend (Go)**: Publishes events (klines, order updates) to NATS JetStream and persists state to NATS KeyValue buckets.
-   **Transport**: `nats.ws` (NATS over WebSockets) bridges the browser to the NATS server.
-   **Frontend (TanStack DB)**: A local database that "subscribes" to these NATS subjects and automatically updates its tables.

### Why TanStack DB?

[TanStack DB](https://tanstack.com/database/latest) (currently in alpha) allows us to query our local data using familiar hooks like `useQuery` or `useLiveQuery`. It handles indexing, persistence (via IndexedDB), and reactivity out of the box.

## Implementation

We created a reusable adapter `natsCollectionOptions` that connects a TanStack DB collection to a NATS source. It supports two modes:
1.  **KeyValue (KV)**: For stateful entities like "Active Orders". It watches a NATS KV bucket for PUT/DEL operations.
2.  **Streams**: For append-only data like "Kline/Candle" history. It subscribes to a subject and inserts new messages as rows.

### The Adapter

Here's a simplified version of our adapter:

```typescript
// natsCollection.ts
import { CollectionConfig, SyncConfig } from '@tanstack/react-db';
import { consumerOpts, JSONCodec } from 'nats.ws';

export function natsCollectionOptions<TItem>(config: NatsConfig): CollectionConfig<TItem> {
  const jc = JSONCodec();

  const sync: SyncConfig<TItem>['sync'] = ({ begin, write, commit }) => {
    let cleanup = () => {};

    const init = async () => {
      const nc = await getNatsConnection();
      const js = nc.jetstream();

      if (config.type === 'kv') {
        const kv = await js.views.kv(config.subject);
        const watcher = await kv.watch();

        (async () => {
          for await (const e of watcher) {
            begin();
            const value = e.value ? jc.decode(e.value) : null;
            if (e.operation === 'DEL') {
              // Handle deletion
              write({ type: 'delete', value: { id: e.key } });
            } else {
              // Handle upsert
              write({ type: 'insert', value });
            }
            commit();
          }
        })();

        cleanup = () => watcher.stop();
      }
    };

    init();
    return cleanup;
  };

  return {
    getKey: (item) => item.id,
    sync: { sync },
  };
}
```

### Usage in the Dashboard

We can now define our collections as if they were standard database tables, but they are magically kept in sync with the backend.

```typescript
// store.ts
export const activeOrders = createCollection<Order>(
  natsCollectionOptions({
    name: 'activeOrders',
    type: 'kv',
    subject: 'kajuna_orders', // NATS KV Bucket
    idKey: 'order_id',
  })
);

export const klines = createCollection<Kline>(
  natsCollectionOptions({
    name: 'ethusdt-klines',
    type: 'stream',
    subject: 'kajuna.kline.ingested.ETHUSDT', // NATS Subject
    idKey: 'open_time',
  })
);
```

### Consuming Data

In our React components, we simply query the data. No WebSocket handlers, no `useEffect` for state merging.

```tsx
function OrderBook() {
  // Always fresh, updated in real-time by the sync adapter
  const orders = useLiveQuery(
      activeOrders.findMany()
  );

  return (
    <div>
      {orders.map(order => (
        <OrderRow key={order.order_id} order={order} />
      ))}
    </div>
  );
}
```

## Benefits

<Callout type="info">
  This architecture effectively decouples the UI from the network transport layer.
</Callout>

1.  **Simplicity**: Components don't know about WebSockets or NATS. They just query the "database".
2.  **Performance**: TanStack DB handles the efficient updating of React state. We can throttle updates or batch them if needed.
3.  **Offline-First**: Since data is persisted to IndexedDB, the dashboard works instantly upon reload, even before the network reconnects.
4.  **Resilience**: If the WebSocket drops, the `nats.ws` client reconnects automatically. When it does, the KV watcher catches up on missed updates, and our local DB becomes consistent again.

## Conclusion

By combining **TanStack DB** with **NATS JetStream**, we've built a robust synchronization engine that feels like magic to develop with. The backend simply "puts" data into NATS, and the frontend "sees" it immediately. No custom protocol needed.
